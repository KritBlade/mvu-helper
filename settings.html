Card config
Save this card's Extra-LLM setup (calls, input regex, groups, timeout) into a [Initmvuhelper] lorebook entry so the card carries it — anyone who loads the card gets it auto-imported (once, without clobbering later edits). The small-LLM connection stays local, so each user assigns it per call in Extra LLM Calls. Re-import is the everyday one: it restores calls the card declares but you're missing, refreshes every field the card owns, and keeps your connection assignments and any call you added by hand. Reach for Reset from card only when the problem is something the card does not declare — a setting left over from an older version, a hand-added call gone bad — because that is exactly what a merge cannot touch. It DISCARDS this card's whole stored setup, connections included.

StatusMenu frame
Where a StatusMenu may load images from, as Content-Security-Policy sources separated by spaces: https: for any https host, or hosts such as cdn.example.com or *.imgur.com. SillyTavern's own images are always allowed. The menu runs in a sandboxed frame that can reach nothing else — no page, no settings, no network — so this list is the one door it has to the outside, and anything the menu is shown can leave through an image URL it chooses. Global (shared across all cards); a menu already on screen picks the change up when it next renders.
Rendering
Removes the <pic> tag from the message — gone from the display, the saved chat, and future context. Applies even when Insert Type is Disable, so galgame reads a clean reply (a lingering tag stalls its text conversion). Turn OFF to keep the tag visible in-chat for troubleshooting — in Replace mode it shows as escaped text (under the image for drawn tags, in place for failed/over-cap ones), so galgame still reads a clean reply. Either way, each prompt is logged to the console (imagegen debug domain), so you can read exactly what was sent to /sd without keeping the tag.

A leading stat_data. is optional — Partner and stat_data.Partner both work. Leave blank to auto-detect by the present-flag record shape. MVU cards only. The per-character boolean field marking on-screen presence. Calls
Max seconds to wait for each PRE/POST call before giving up on it — a stalled call then resolves as empty and the others proceed, so one hung request can't freeze the reply (PRE) or the turn's record write (POST). Per card. Default 60. Each call sends the lorebook entries named [callName] … as a system block to its connection profile, prefixed by any group blocks it's checked into (below). Put shared content (roster/schema) in a group several calls share instead of copying into each. PRE calls run BEFORE the main reply (over the last user message) and inject their output into the prompt; POST calls run AFTER the reply (over the AI's prose).
Shared groups
A group has a [tag] and a set of member calls (checkboxes). Its [tag] … lorebook entries are read by every member. Calls can be in more than one group.
